# Longest Path in a Directed Acyclic Graph (DAG)
### The Problem
The full problem statement is posted [here](https://github.com/DonFactorial/dag-longest-path/blob/main/ProblemStatement.pdf). Briefly, the name of the problem is The Timelike Tourist. There are 1,000 must-see events this tourist wants to visit, each of which has an associated point in spacetime $(t,x,y)$. The Timelike Tourist can only travel forward in time (i.e., $t_\textrm{now}<t_\textrm{next}$) and can only travel timelike distances (i.e., $D(P_\textrm{now},P_\textrm{next})<0$ for the definition of distance $D$ given in the problem statement). This definition of distance is not the Euclidean one (which doesn't allow negative values). If this is new to you, it's not too important, just know that in relativity, negative distance is allowed and makes sense (and is called timelike, hence the name of the problem). A path that follows these constraints is called chronological. The Timelike Tourist's journey must be chronological and can begin and end at any event. What is the journey that allows the Timelike Tourist to see as many must-see events as possible?

### The Solution
The first thing to notice is that this set of events and constraints forms a directed acyclic graph (DAG). A directed graph is a set of nodes (points) and edges (arrows) that connect them. A directed acyclic graph has no cycles (loops), which is caused by the constraint that you can only move forward in time. Two nodes can be connected with an edge if one comes before the other in time and they are separated by negative distance. An important note is that the direction of each edge is determined solely by the nodes' respective times, not their distance. With this in mind, this problem can be solved in two steps: (1) create a topological sort of the list of events and (2) use dynamic programming to obtain the longest path starting from each node.

For the first step, a topological sort is an ordering of nodes in a DAG that ensure you process each node from "beginning" to "end." There are usually many possible topological sorts, but any particular one will do for our purposes. In this case, there is a very quick way to obtain one that doesn't require implementing Kahn's algorithm or similar: ordering by time. The DAG is constructed so that nodes are already ordered by time, so this is the topological sort that is the most natural.

For the second step, we get to see the fruit of our effort in creating a topological sort. Create an array to store the longest path you can find that *ends* at each node. Starting from the first node in the sort (let's say index 0), no nodes come before it, so the best path that ends here is just the node itself, so we store the array [0] in our longest path array. Let's say that node 471 is the next in our sort. Look at all of its predecessors (nodes that point *to* it), choose the one with the longest path, and append node 471 to it. Since this is the second one in line, we store [0, 471] in the 471 position of our longest path array. We can proceed just like this through the topological sort, listing its predecessors, selecting the one with the longest path, and adding our current node to it. At the end, what we have is the exact array of longest path arrays we wanted. All we have to do now is take the longest of those arrays and that's our answer.

If you do all this, you get a path of length 61: [1, 2, 531, 64, 941, 3, 959, 747, 431, 140, 145, 519, 427, 734, 241, 781, 173, 629, 547, 238, 119, 116, 137, 838, 688, 199, 82, 476, 988, 969, 224, 663, 101, 658, 423, 972, 785, 742, 802, 126, 193, 75, 206, 240, 84, 105, 441, 976, 737, 274, 80, 627, 5, 542, 316, 365, 96, 513, 466, 374, 322]. Note these indices start from 1 to match the problem statement. Here's a plot of this optimal path.
